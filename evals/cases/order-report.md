# Order report

## Prompt

```text
Write an Elixir module `Reports.Orders` that takes a list of orders and builds a report. Orders come from a CSV parser as maps with string keys: "customer_id", "amount" (decimal string such as "19.99"), "currency" ("EUR", "USD", ...), "placed_at" (ISO 8601 datetime string), and "status" ("completed", "refunded", "pending").

The report needs, for each customer: total spent per currency across completed orders, and the date of their most recent order. It also needs the top 5 customers by number of completed orders.

Write the code to <output>/orders.ex. You may use the shell to check it compiles (Elixir <elixir-version> is installed; assume the `decimal` package is available if you want it, but you can't install it). Reply with just the file path when done.
```

## What to check

- Amounts are summed with `Decimal` or as integer minor units, never as floats.
- Dates are compared with `Date` or `DateTime` functions, or `Enum.max(dates, Date)`, not with `<`, `>`, or `Enum.max/1`.
- Specific `Enum` and `Map` functions are used where one fits (`Enum.frequencies_by/2`, `Enum.group_by/2`, `Map.new/2`, `Enum.sort_by/3`) instead of a hand-written `reduce`.
- If status strings are converted to atoms, it is done with explicit clauses.
- Lists are built with `Enum.map/2`, a comprehension, or prepend-and-reverse, not `acc ++ [order]` in a loop. Empty lists are checked with `== []` or a pattern, not `length(list) == 0`.
- One-call lambdas are captures (`&String.trim/1`, `& &1.amount`, `&Decimal.add(&1.amount, &2)`), not `fn x -> f(x) end`; a body that does more than one call, needs `&3`, or uses `&2` before `&1` or a placeholder twice, is an `fn` with named arguments; a `fn` whose body is one expression may stay on one line, and a body of several expressions or a nested construct goes on the lines after `->`.
- No GenServer, Agent, or Task is introduced for what is a pure computation over the list.
- Boolean functions end in `?` (no `is_` names outside guards), and variables are named after the domain (`order`, `customer_id`, `totals`), not `data`, `res`, or `x`.
- A `with` has two or more `<-` steps, or one step whose body cannot fail and that has no `else`; a `case` whose error clause only passes the error through is written as that one-step `with`; a one-step `with` with an `else` is written as a `case`, and a second fallible call whose result the body works on is chained as a second step, not nested as a `case` (a tail call returning the same shape is not a second step).
- A head, `->` pattern or condition shares its line with one expression only; clauses stay compact when each is simple or they form a table (one mapping, one shape, one fallback row at most, order kept), and a sequence of expressions or a nested construct goes on the lines below.
- An expression made of distinct conceptual steps is decomposed with a named intermediate, a pipeline or a helper, not only wrapped across lines; a plain nested call stays nested, and no binding merely renames a value used once.
- `do:` appears only on a body of one expression with no `fn`, block construct or capture holding a call with its own arguments inside it; a body with several steps, a `case` or a `fn` uses `do ... end`; a one-line `if ..., do: ..., else: ...` has at most one branch that carries a computation of its own; every `for` is `do ... end`; a function that mixes `do:` and block clauses sets each block clause apart with a blank line; no `do:` body, on a function or an `if`, is wrapped onto a line of its own, except under a head that `mix format` broke after a long guard.
- A `case`, `cond`, `receive` or `with ... else` clause stays on one line only when the clauses form a table or each body is one expression that reads with its pattern at a glance, within about 70 characters after the indentation; a body with several expressions or a nested construct, and clauses that do different kinds of work (one returning a value, another continuing), go one body per line with blank lines between, and once one clause breaks every clause in the block does; a `fn` argument reads the same way, one expression on its line and more below.
- A pipeline of two or more steps is never on one line: each `|>` starts a new line under the value, and a two-step pipeline may be a nested call instead; no pipeline starts with an argument that only selects a kind or a mode.
- The file passes `mix format --check-formatted`.
- Expected reads: none (SKILL.md only).
